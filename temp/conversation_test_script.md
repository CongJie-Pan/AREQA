# Topic Finder 測試劇本 v2：大安區心理諮商預約難

來源：`temp/Gemini-大安區心理諮商預約難度分析-20261124-1725.md`

依 2026-11-24 的修改更新：
- 教練回覆變短，不先稱讚，不替使用者下結論。
- 換階段時，教練會在對話裡說明這階段要做什麼。
- 輸入框上方會出現「前往第 N 階段」按鈕；也可以直接在對話裡說要換階段。
- 題目卡精簡：草稿只列出變動的部分，按鈕是「需要／不需要」，其他內容收進「其他紀錄」。
- 「這輪先看」和回頭檢查都改在對話裡進行。
- 每次題目卡變動都會記一筆狀態 log。

「輸入」包含打字和點按鈕；「預期輸出」分成教練回覆、題目卡和狀態 log。

**前置**
- 開一個新的 Topic Finder 對話，介面語言設為繁體中文。
- **「網路搜尋」保持關閉**（上一輪實測時是開著的，導致回覆帶網址和數據）。
- 後端已套用 migration `20261125000000_research_topic_card_events.sql`。

**每一輪都要符合的通則**（下面各輪不再重複寫）
- 回覆 3–6 句，不用標題（#、###、一二三），結尾只有一個問題，不給 A/B 選項。
- 開頭不稱讚（不說「非常敏銳／精準／透徹」之類的話）。
- 不編造案例、數據、網址或論文。
- 回覆裡不出現【回頭檢查】【本輪缺口】【進入新階段】【可以前進】等內部標籤。
- 對使用者只說「第 N 階段」，不說「關」「篩子」「操作化」「缺口」。
- 教練不說「我已經幫你切換到第 N 階段」，也不宣告某個階段已經完成。
- 題目卡上**不會出現**「這輪先看」「換一個」「下一階段 →」，以及「要不要採用、何時換階段都由你決定」這句提示。

  - 第一行是標題和小箭頭，第二行是灰色的「候選題目 · 看得見的證據 · 淘汰 1 · 反問 N · 版本 N」。
  - 展開後各組小標旁有數量；內容是一般字重、左邊一條細線。
  - 版本紀錄最新的在最上面，每版說明最多兩句。
- 手機寬度下題目卡沒有左右捲動。

## 第 17 輪｜狀態 log 檢查（給開發者）

**輸入**：用登入後的 Bearer token 呼叫 `GET /api/research-coach/{對話ID}/log`（後端是 `GET /api/v1/research-coach/{對話ID}/card/log`）。

**預期輸出**：時間軸依時間排序，每筆有 `event`、`source`、`stage`、`version` 和完整快照 `state`，大致如下：

| 劇本步驟 | 事件（來源） |
|---|---|
| 每輪回答後 AI 提出草稿 | `proposed`（background） |
| 第 1、3、7、8、10、12、13 輪按「需要」 | `adopted`（api），版本依序加 1，到 v8 |
| 第 2 輪按「不需要」 | `rejected`（api），版本不變 |
| 第 4 輪、第 13 輪按對話裡的按鈕 | `stage_set`（chat），分別是 stage 2 和 stage 4 |
| 第 8 輪、第 13 輪按題目卡階段按鈕 | `stage_set`（api），stage 3 |
| 第 9 輪打「我們到第 4 階段」 | `stage_set`（chat），stage 4 |
| 第 9 輪問「第 5 階段要做什麼？」 | 沒有任何事件 |
| 第 11 輪說「先放著」之後 | `focus_skipped`（background），`focus_kind` 是 `measure` |
| 第 13 輪採用新的母問題 | `adopted` 之後緊接著 `review_set`（api） |
| 第 13 輪「好，那接下來呢？」回答之後 | `review_cleared`（background） |
| 第 14 輪打「我們到第五階段好了」 | `stage_set`（chat），stage 5 |

- 不論是快照還是後端終端機日誌，都只有你自己的資料；終端機日誌裡不會出現題目卡的文字。
