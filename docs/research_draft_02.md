## 0. 背景與研究緣起 (Background & Why This Matters)

現在市面上很多「AI 學習伴讀」系統，運作方式都很簡單粗暴：系統會把學生過去所有的**聊天紀錄 (歷史記憶)**，加上一句通用的指示（例如：請一步步引導學生），全部塞進 Prompt 裡，然後交給 ChatGPT 或 Gemini 讓它自己想辦法回答。

這種做法初期看起來很酷，但時間一久就會出事：
1. **AI 會精神分裂**：記憶塞得太多，AI 會搞混學生昨天問的數學跟今天問的英文，開始胡言亂語（這叫上下文污染）。
2. **AI 只會給答案，不會教**：因為系統沒有明確告訴 AI 學生現在「卡在哪個具體的觀念」，AI 為了省事，往往會直接把答案印出來，而不是像個好老師一樣給予提示（鷹架）。

因此，本研究希望打造一個**「結構化」的自適應教學架構**。系統在回答前，會先做兩件事：
1. **診斷 (Diagnosis)**：找出學生對這題需要的觀念，到底是懂了，還是有錯誤的迷思？
2. **決策 (Decision)**：既然學生卡在這裡，我是該用「拆解問題」還是「舉例說明」來教他？
最後，系統才把這個「明確的處方」交給 LLM 去產出文字。我們希望能證明，這種做法比單純「塞 Prompt」好得多。

## 2. 研究動機與面臨的挑戰 (Motivation & Challenges)

目前教育 AI 的主流做法是**「記憶增強提示 (Memory-Augmented Prompting)」**，但在實際應用中，這遇到了三個致命挑戰：

1. **AI 搞不清楚學生到底哪裡不懂 (缺乏明確狀態)**：
   單純把對話丟給 LLM，LLM 很難精準判斷學生是「完全沒學過這個名詞」還是「把 A 觀念跟 B 觀念搞混了」。
2. **記越多反而越笨 (記憶干擾與 Token 浪費)**：
   隨著聊天越來越長，把所有對話塞給 LLM 會導致它注意力分散（Lost in the middle）。這不僅浪費 API 費用，還會讓 LLM 抓錯重點，給出莫名其妙的建議。
3. **只會給答案，不會給提示 (教學策略不一致)**：
   沒有明確的系統控制，LLM 很容易「破功」，直接把整題的答案和程式碼印出來，剝奪了學生自己思考和解題的機會。

**我們的解法：**
結合 EDF (證據-決策-回饋) 循環，系統不讓 LLM 自由發揮，而是強制系統先列出「局部知識節點」，更新「學習者狀態（電子病歷）」，系統選定「教學策略」後，才讓 LLM 照著策略開口說話。

## 3. 研究問題 (Research Questions, RQs)

本研究將進行一場 A/B 測試，比較**「舊做法：直接塞記憶 (Baseline)」**與**「新做法：先診斷再教學 (Proposed)」**，並回答以下四個問題：

*   **RQ1 (把脈準不準？)**：新架構產出的「學生懂不懂這個觀念」的診斷結果，是不是跟真正的人類老師判斷的一樣準？
*   **RQ2 (開藥對不對？)**：新架構選出來的「教學方法（如：拆解問題）」，是不是比 LLM 自由發揮更適合學生現在的狀況？
*   **RQ3 (能省多少資源？)**：新架構是不是能成功減少把一堆廢話記憶塞給 LLM，進而降低 Token 成本並減少 LLM 的幻覺？
*   **RQ4 (學生進步多嗎？)**：在模型一樣的前提下，用新架構教出來的學生，測驗成績與知識保留率是不是比較高？

## 4. 研究目標與下一步 (Objectives)

為了回答上述問題，我們接下來必須完成以下目標：

1.  **設計學生的「電子病歷」(定義學習者模型)**：
    寫出一個清晰的 JSON 格式，用來記錄學生對某個觀念的「掌握度」、「錯誤迷思」、「判斷證據來源」與「信心水準」。這將取代傳統的對話歷史紀錄。
2.  **建立公平的「考場」(離線評估環境)**：
    準備 5~10 個固定的考題與學生的模擬回答。用這套考題分別去跑「舊做法」跟「新做法」，看看兩邊的產出有什麼不同。
3.  **算清楚「成本與效益」**：
    精確測量新架構雖然可能教得比較好，但會不會因為多跑了幾次診斷，導致系統變慢 (Latency) 或 API 費用增加？確認這個代價是否值得。
4.  **總結成設計準則**：
    如果證明有效，將這套「診斷 $\rightarrow$ 決策 $\rightarrow$ 生成」的流程寫成設計指南，提供給未來想做教育 AI 的開發者參考。
