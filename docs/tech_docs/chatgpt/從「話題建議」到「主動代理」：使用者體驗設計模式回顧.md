# 從「話題建議」到「主動代理」：使用者體驗設計模式回顧

## 混合主動式介面與主動代理設計模式  
- **即時適應式界面 (Just-in-Time UI)**：系統不再使用靜態頁面和固定流程，而是根據使用者當前情境動態組合介面元素，主動在使用者需要時給予提示或功能入口。如 Signal Path 所述，「即時介面」會在正確時機把對應的功能帶給使用者，界面變成與使用者展開對話，主動提示建議或行動，而不是讓使用者自己導航。設計上必須具備情境感知，透過感測使用者意圖或階段，自動呈現相應選項；同時避免侵入感（例如將介面元件淡入淡出、使用可調節的主動性開關）以維持使用者控制感。  
- **行為感知主動支援 (Behavior-Aware Assistance)**：代理系統持續監控使用者互動特徵，主動偵測「需要幫助」的時機點，再發送建議或自動執行半成品任務。例如 Zhao 等 (2025) 的 ProactiveVA 系統會根據使用者的長時間思考、重複操作或錯誤輸入等行為特徵，識別用戶可能陷入困惑並觸發即時協助。此模式下，系統由感知模組分析使用者行為，推理模組判斷隱含意圖，然後透過介面動作模組自動提供建議或展開選單。使用者依然保持對最終決策的控制（可在設定中調整代理介入頻率或類型），以避免過度打擾。  
- **可解釋與可控的建議機制 (Explainable, Controllable Hints)**：主動提示應融合可解釋的機制，減少使用者驚訝或反感。例如 Viswanath 等人指出，代理介入前應提供適當解釋或提示，讓使用者理解建議的來源與目的，以增進信任並防止「上下文污染」。同時設計上要平衡介入時機與頻率：可以透過階段性揭露建議或信心度視覺化，讓使用者決定是否採納，並預留取消或回饋的管道。例如 Rintel 等 (2025) 建議，系統應「主動浮現被忽略的任務或觀點，同時提供隨需選擇的被動協助」，這種主動提醒加被動支援的混合模式可有效降低使用者認知負擔。  

## 使用者畫像驅動的主動工作流自動化與認知支持模式  
- **通用使用者模型 (General User Model, GUM) 和主動代理 (GUMBO)**：Shaikh 等 (2025) 提出構建多模態的「通用使用者模型」架構，持續觀察使用者在電腦上的各種互動（文字、視覺等），將其轉換為信心加權的使用者命題（例如使用者正在準備婚禮、正在研究論文等）。在此基礎上，可實現所謂的「GUMBO」主動代理：代理使用該模型來預測使用者潛在需求，並自動執行有用的任務（如預先產生草稿、整理相關資源）。實踐中可視為將使用者畫像融入 RAG 或多代理流程中，讓系統在背景中持續更新使用者狀態並在適當時機自動推送或執行工作流程。該模式在實驗中證明能準確推斷使用者需求，並讓代理「自動發現並執行使用者未曾明確提出的有用動作」。  
- **認知狀態感知的時機預測 (Cognitive State–Aware Timing)**：Pu 等 (2025) 的 ProMemAssist 項目將工作記憶模型應用於可穿戴裝置，實時估計使用者的工作記憶佔用程度，並據此預測最佳支援時機。其系統示範了基於工作記憶狀態的主動建議，在使用者認知負荷較低且更容易接受時發送提示，可以大幅減少不必要的打斷並提高參與度。此模式強調針對認知負荷或工作階段設計介入時機（例如任務初期、完成階段提示檢查），以及平衡助益和中斷成本的預測機制，可應用於學習或複雜作業場景作為「小幫手」功能。  
- **錯誤預防與信息提示 (Error-Checking Cognitive Support)**：代理可主動執行錯誤檢測或待辦提醒來支持認知工作。舉例而言，Zhao 等的 ProactiveVA 系統可以分析使用者輸入的筆記內容，對比後端資料，如果發現矛盾或缺漏，便自動向使用者發出糾正或補充的提示。這種模式將使用者畫像（此處為正在進行的分析任務和相關資料）用於生成提醒，可類比於在用戶作業期間提供「防呆檢查表」：系統根據任務上下文與使用者偏好（例如常見失誤模式）自動提供提醒或輔助。同類模式還可實現如「自省式互動支持」：例如設計系統要求使用者先陳述自己的推理（ExtendAI 模式），再給出建議，藉此保持使用者控制感和批判思考。  

## 結論與開發者 MVP 功能建議  

1. **時機感知的建議彈窗**：實作一套時序觸發機制，例如偵測使用者長時間停頓或連續錯誤輸入時，自動彈出相關提示或建議清單，並搭配信心度指示或淡入淡出動畫以降低侵入感。這可參考 ProactiveVA 等研究中「當使用者疑惑或停頓時自動彈出協助」的作法。實際上可利用前端程式持續監聽用戶操作，並由後端 LLM 生成針對當前內容的建議文本或操作建議。  
2. **半成品內容預填產生器**：為特定工作流程（如報告撰寫、會議記錄）加入「草稿生成模式」，系統根據使用者歷史偏好或先前對話內容，主動生成初步大綱或文本片段給使用者校正。舉例來說，當用戶開啟文件編輯時，系統可先填入標題、提綱、示例段落等，使用者僅需微調或增補。如 Shaikh 等(2025) 及延伸工作所示，利用累積的使用者模型自動草擬內容，能顯著提升工作效率。實現上可在後端串接 RAG 檢索用戶常用資料和記憶摘要，再用 LLM API 生成預備文本。  
3. **認知支持提醒機制**：在用戶操作過程中加入檢錯與提醒功能。例如，在任務關鍵節點檢測可能的遺漏（如表單未填完、重要參數設定錯誤）時，自動彈出提醒視窗，或者定期在側邊欄顯示「當前任務檢查表」。可參考 ProactiveVA 的「內容不一致提醒」設計，和 Microsoft Tools for Thought 建議的「主動提示常被忽略任務」思路。具體而言，開發者可將常見失誤規則編碼或將用戶畫像中敏感資訊標註，再結合 LLM 生成針對性建議，形成「助手小幫手」式的防呆機制。
