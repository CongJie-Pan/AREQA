# AI 系統的長期記憶管理與動態提取策略

## 短期工作記憶 vs 長期記憶的固化與轉換  
- **記憶總結與反思 (Summarization/Reflection)：** 以 Generative Agents (Park et al., UIST ’23) 為例，系統將對話和事件以自然語言形式記錄在「記憶流」中，並定期利用 LLM 生成反思，將多個片段記憶總結成高階摘要，以增進長期記憶一致性。此模式類似人類將短期經歷「凝練」成長期知識，並僅在需要時檢索相關事件，避免一次將所有資訊置入上下文造成污染。  
- **人類式遺忘與強化 (Forgetting Curve)：** 如 MemoryBank (Zhong et al., 2023) 所採用的演算法，模仿艾賓浩斯遺忘曲線，根據時間流逝和事件重要性動態調整記憶權重。記憶在經過多次檢索或具有重要性時會被強化，反之隨時間衰減遺忘。這種模式允許系統主動「忘卻」不再重要的對話細節，而保留核心經驗，有助於長期語意記憶的有效管理。  
- **結構化連結記憶網絡 (Zettelkasten)**：A-MEM (Xu et al., NeurIPS ’25) 提出將記憶組織成節點與動態連結的網絡，採用類似索引卡法 (Zettelkasten) 的原則。每次新增記憶都生成帶有多重屬性（情境描述、關鍵詞等）的「筆記」，系統自動分析舊有記憶中的相關性並建立連結，必要時更新既有條目。此設計模式強調記憶之間的關聯性，有助於系統從碎片記憶中發現隱含聯繫，並在需要時進行動態整合。  

## RAG/Agent 架構下的記憶提取與上下文注入  
- **向量檢索＋即時擴充 (Embedding Retrieval + Just-in-Time Tooling)：** 多數實踐採用嵌入式檢索 (如 RAG) 先找出最相關的長期記憶，再輔以工具進行「即時載入」。以 Claude Code 為例，系統預先將重要文件放入上下文，然後運用工具（如 grep、glob 等）在需要時即時檢索目標資訊。此混合策略避免一次性載入過多內容並減少過時索引問題，同時保障對話生成所需的關鍵資訊可被及時補充。  
- **結構化筆記／抓取筆記 (Scratchpad Memory)：** Agent 定期將關鍵對話或狀態寫入外部記憶（如筆記檔、數據庫），並在後續需要時再拉回上下文。這種「寫入式記憶」策略類似人類做筆記，在對話歷程外持久化信息。例如 Anthropic 的多代理研究示例和 LangChain “scratchpad” 策略，都將輔助工具視作可寫入的筆記，讓 Agent 在需要時檢索先前保存的訊息。透過外部筆記，系統可在長對話中保持關鍵上下文而不致污染主上下文。  
- **上下文壓縮 (Context Compaction)：** 當對話接近上下文窗口限制時，系統會將歷史內容摘要並重啟新窗口，以僅保留核心信息。例如 Claude Code 在超過長度時，會將對話歷程提交模型進行壓縮總結，只保留架構設計、未解決問題等關鍵細節，同時丟棄冗余輸出。這種即時壓縮可維持長期一致性，又減少上下文干擾，避免因無關或重複內容導致的效能下降。  

## 結論與MVP建議  
- **自動記憶摘要功能：** 實作對話內容自動摘要模組，將短期交互經驗定期轉化為長期記憶（類似 Generative Agents 的反思過程）。例如，每隔 N 輪對話，使用 LLM 自動對先前聊天要點生成摘要並儲存於記憶庫，以減少上下文負擔。  
- **外部記憶查詢工具：** 整合長期記憶庫（例如向量數據庫，如 LangChain/LlamaIndex 提供的記憶儲存）並搭配檢索介面。讓 Agent 在需要時發出查詢，僅將檢索到的高相關片段注入當前上下文，避免全文插入。可參考 embedding＋BM25 的檢索策略，並結合即時工具載入機制。  
- **持久化筆記與反思機制：** 為 Agent 增設「筆記」或「日誌」模組，使其能將關鍵資訊、用戶偏好等持久化保存。在每次對話或特定觸發點後，讓模型生成反思並更新這些筆記。如此 Agent 在未來互動時能透過查閱筆記提高回應相關度，並避免在主上下文中重覆無用信息。
