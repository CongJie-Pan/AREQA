# 小紅問答系統 — 延伸問題（Suggested Questions）功能實作規劃報告

## 一、理論基礎：Dynamic Contexts 論文解讀

### 論文背景

本節說明「延伸問題生成可以用動態上下文提示（Dynamic Context Prompting）配合小型模型完成，效果並不亞於大模型」此論點的學術依據。

此論點源自 2024 年發表於 arXiv 的研究論文：**《Dynamic Contexts for Generating Suggestion Questions in RAG Based Conversational Systems》**（Tayal & Tyagi, University of Illinois Chicago & Procter & Gamble）。[^1]

論文核心主張是：RAG 型對話系統的核心問題之一，是用戶不了解系統能回答什麼，導致提問模糊或方向錯誤。該研究提出**動態上下文提示（Dynamic Contexts Approach）**來自動生成「系統有能力回答的延伸問題」，以引導用戶進一步探索。[^1]

### Dynamic Contexts 的兩個核心組件

論文提出的 Dynamic Contexts 框架由兩個核心元素組成：[^1]

1. **動態 Few-Shot 示例（Dynamic Few-Shot Examples）**：不使用靜態固定的示例，而是每次根據用戶當前 Query，從資料集中動態選取**最相似**的（問題、回答、延伸問題）三元組作為 In-Context Learning 的範例。這確保示例與當前問題結構最接近，而非千篇一律。

2. **動態檢索上下文（Dynamically Retrieved Contexts）**：同時從知識庫中動態檢索與 Query 最相關的 4 個文獻片段，注入 Prompt 中。這讓生成的延伸問題必然是「系統有能力回答的」，而非憑空捏造。

最終的 Prompt 結構為：`[系統角色] + [3組動態Few-Shot示例（Q+A+Suggestion）] + [用戶Query] + [4個動態檢索片段]`。[^1]

### 論文中的關鍵實驗結果

論文透過比較四種 Prompting 策略的準確率，證明了 Dynamic Contexts 方法的優越性：[^1]

| 方法 | ChatGPT | Claude-2 | GPT-4 |
|------|---------|----------|-------|
| Zero-Shot（無示例） | 35 | 30 | 43 |
| Few-Shot（靜態示例） | 42 | 35 | 40 |
| Dynamic Few-Shot | 42 | 35 | 43 |
| **Dynamic Contexts（本文方法）** | **44** | **44** | **46** |

（滿分 48，數值為 48 個測試樣本中正確生成延伸問題的數量）[^1]

關鍵發現如下：[^1]

- **Dynamic Contexts 使 Claude-2 從 30 分提升至 44 分**，提升幅度達 46.7%，這意味著能力較弱的模型在搭配動態上下文後，表現幾乎與 GPT-4（最強模型，46/48）持平。
- 靜態 Few-Shot 有一個明顯缺陷：**「示例複製效應」**——模型傾向於產生與示例結構完全相同的問題，缺乏多樣性。Dynamic Few-Shot 雖緩解此問題，但仍未突破瓶頸。
- Dynamic Contexts 的核心優勢是同時提供了**知識邊界（檢索上下文）**與**格式範例（動態 Few-Shot）**，兩者缺一不可。
- 消融實驗（Ablation Study）顯示，調換 Prompt 中 Query 與 Context 的順序對結果**無顯著影響**，架構的健壯性很高。[^1]

### 對小紅系統的核心啟示

論文的實驗已證明：**透過 Dynamic Contexts 方法，即便是較小的模型，也能生成與最大模型（GPT-4）幾乎相當品質的延伸問題**。這直接支持「使用現有的 `Qwen2.5-7B-Instruct` 標題模型來承擔延伸問題生成任務」的技術決策，無需啟動主模型（`XiaoHong-v1`）。[^1]

## 二、系統設計：如何映射到小紅架構

### 小紅版 Dynamic Contexts 的設計轉化

論文的框架可直接對應至小紅的現有架構：

| 論文元素 | 小紅架構對應 |
|----------|-------------|
| 動態 Few-Shot 示例（Q+A+Suggestion） | 預先設計 10~15 組人工標注的紅樓夢問答延伸問題範例 |
| 動態檢索上下文（4個片段） | 直接**複用** RAG 管線已檢索出的 Top-K 文獻片段（`reranked_results`），零額外成本 |
| 生成模型 | `Qwen2.5-7B-Instruct` @ OpenRouter（標題生成模型） |
| 觸發時機 | 主模型（`XiaoHong-v1`）完成串流輸出並發送 `[DONE]` 後，Background Task 執行 |
| 傳回方式 | 新增 SSE `event: suggestions` 事件，不影響主流程延遲 |

這個設計完美利用了「RAG 管線的副產品」（已存在的 reranked_results），將論文中需要額外進行的「動態檢索上下文」步驟成本降為零。

### 整體資料流（完整版）

```
主模型串流輸出結束 → data: [DONE] 發送至前端
        │
        ▼ (非同步 Background Task 開始)
        │
        ├─ 輸入1：user_query（用戶原始問題）
        ├─ 輸入2：reranked_results（已有，直接複用）
        └─ 輸入3：answer_text 前 400 字（串流過程中累積）
        │
        ▼
  [Suggestion Generator]
  Qwen2.5-7B @ OpenRouter
  使用 Dynamic Contexts Prompt
        │
        ▼
  解析 JSON → ["問題1", "問題2", "問題3"]
        │
        ▼
  event: suggestions
  data: ["...","...","..."]  → 前端顯示延伸問題按鈕
```

## 三、後端實作：`suggestion_service.py`

```python
# suggestion_service.py
import os
import json
from openai import AsyncOpenAI

openrouter_client = AsyncOpenAI(
    api_key=os.environ["OPENROUTER_API_KEY"],
    base_url="https://openrouter.ai/api/v1",
)

# 人工標注的 Dynamic Few-Shot 示例（Q + A摘要 + 延伸問題三元組）
# 這等同於論文中的 "dynamic few-shot examples" 的靜態種子庫，
# 實際呼叫時可用 Embedding 相似度選出最接近的 3 組
FEW_SHOT_EXAMPLES = """
[範例一]
用戶問題：賈寶玉為什麼不喜歡讀四書五經？
回答摘要：寶玉天性叛逆，認為仕途功名是「國賊祿鬼」，對女兒家的靈秀更為欣賞。
建議問題：["寶玉對仕途的態度如何影響他與賈政的關係？", "《紅樓夢》中有哪些人物積極追求仕途？", "寶玉的人生觀與魏晉名士有何相通之處？"]

[範例二]
用戶問題：林黛玉和薛寶釵的性格有什麼不同？
回答摘要：黛玉多愁善感、才情縱橫；寶釵圓融世故、處事周全，代表「情」與「禮」的對立。
建議問題：["金陵十二釵正冊中黛玉和寶釵的判詞各是什麼？", "大觀園中其他人對黛玉和寶釵的態度有何不同？", "曹雪芹對這兩個角色的設計意圖是什麼？"]

[範例三]
用戶問題：《紅樓夢》的主題思想是什麼？
回答摘要：全書以賈府盛衰映照社會興亡，以寶黛愛情悲劇探討情與世俗的衝突，充滿濃郁的虛無感與悲憫情懷。
建議問題：["《紅樓夢》的「色空觀」從哪些情節體現出來？", "賈府的衰敗與清代社會背景有何關聯？", "前八十回與後四十回的主題風格有何差異？"]
"""

SUGGESTION_SYSTEM_PROMPT = f"""你是《紅樓夢》與中國古典文學問答系統「小紅」的延伸問題生成器。

你的任務是根據用戶的問題、模型的回答摘要，以及相關的古籍文本片段，
生成 3 個繁體中文的延伸問題，讓用戶可以繼續深入探索。

【重要規則】
- 每個問題必須在 25 字以內
- 所有問題都必須是系統能從提供的古籍片段中回答的（不能超出上下文範疇）
- 問題要有多樣性，角度各不相同（如：人物、情節、主題、比較等）
- 禁止生成與紅樓夢或國學無關的問題
- 輸出純 JSON：{{"suggestions": ["問題1", "問題2", "問題3"]}}

【示範（動態 Few-Shot）】
{FEW_SHOT_EXAMPLES}

現在請根據以下資訊生成延伸問題："""


async def generate_suggestions(
    user_query: str,
    answer_text: str,
    reranked_contexts: list[dict],  # 直接複用 RAG 管線的 reranked_results
) -> list[str]:
    """
    使用 Dynamic Contexts 方法生成 3 個延伸問題。
    reranked_contexts: 格式為 [{"title": "...", "snippet": "...", "score": 0.9}, ...]
    """
    # 組裝動態檢索上下文（論文中的 "dynamically retrieved contexts"）
    context_text = ""
    for i, ctx in enumerate(reranked_contexts[:4], 1):  # 取 Top-4，與論文一致
        context_text += f"[片段{i}] {ctx.get('title', '')}: {ctx.get('snippet', '')}\n\n"

    user_content = f"""用戶問題：{user_query}

回答摘要（前400字）：
{answer_text[:400]}

相關古籍文本片段（請確保生成的問題可以從以下片段中找到答案）：
{context_text}"""

    try:
        response = await openrouter_client.chat.completions.create(
            model="qwen/qwen2.5-7b-instruct",
            messages=[
                {"role": "system", "content": SUGGESTION_SYSTEM_PROMPT},
                {"role": "user", "content": user_content},
            ],
            response_format={"type": "json_object"},
            max_tokens=200,
            temperature=0.7,  # 稍高溫度，增加問題多樣性
            timeout=5.0,
        )
        result = json.loads(response.choices.message.content)
        suggestions = result.get("suggestions", [])
        # 基本品質過濾：確保有 3 個問題且每個不超過 30 字
        return [s for s in suggestions if len(s) <= 30][:3]

    except Exception as e:
        print(f"[SuggestionError] {e}")
        return []  # 靜默失敗，不影響主流程
```

## 四、後端整合：修改主串流端點

延伸問題生成必須在主模型完成輸出（`[DONE]`）**之後**觸發，且不能阻塞 `[DONE]` 的發送。[^2]

```python
# main.py (FastAPI) — 修改 original_rag_and_llm_pipeline

from suggestion_service import generate_suggestions

async def original_rag_and_llm_pipeline(user_query: str, body: dict, reranked_results: list):
    answer_buffer = []  # 累積串流文字

    # ... （原有 RAG 流程：HyDE、雙路檢索、Rerank 等）

    # ── 主模型 SSE 串流輸出 ──
    async for chunk in hf_stream_response:
        content = chunk["choices"]["delta"].get("content", "")
        if content:
            answer_buffer.append(content)
        yield f"data: {json.dumps(chunk, ensure_ascii=False)}\n\n"

    # ── 主流程結束 ──
    yield "data: [DONE]\n\n"

    # ── 非同步觸發延伸問題生成 ──
    # 注意：await 放在 [DONE] 之後，不阻塞主回答的送達
    answer_text = "".join(answer_buffer)

    suggestions = await generate_suggestions(
        user_query=user_query,
        answer_text=answer_text,
        reranked_contexts=reranked_results,  # 直接傳入已有的 reranked_results
    )

    if suggestions:
        suggestions_payload = json.dumps(suggestions, ensure_ascii=False)
        yield f"event: suggestions\ndata: {suggestions_payload}\n\n"
```

### 完整 SSE 資料流（加入延伸問題後）

```
event: status  → {"status": "searching_dense", "message": "📖 翻閱古籍索引..."}
event: sources → [{"title": "紅樓夢", "snippet": "...", "score": 0.9}]
data: {"choices": [{"delta": {"content": "<think>\n這是一個關於..."}}]}
data: {"choices": [{"delta": {"content": "\n</think>\n正式回答如下..."}}]}
data: [DONE]
event: suggestions → ["黛玉的詩詞風格受哪位古代詩人影響最深？", "大觀園詩社還有哪些成員？", "寶玉評價黛玉詩才的具體段落出自第幾回？"]
```

## 五、前端實作：Next.js 整合

### Zustand Store 擴充

```typescript

interface ChatState {
  messages: Message[];
  suggestions: string[];          // 新增
  setSuggestions: (s: string[]) => void;  // 新增
  clearSuggestions: () => void;   // 新增
}

export const useChatStore = create<ChatState>((set) => ({
  messages: [],
  suggestions: [],
  setSuggestions: (suggestions) => set({ suggestions }),
  clearSuggestions: () => set({ suggestions: [] }),
}));
```

### SSE 事件監聽

```typescript
// hooks/useStreamParser.ts

// 用戶提交新問題時，先清空舊的延伸問題
useChatStore.getState().clearSuggestions();

// 監聽延伸問題事件（在 [DONE] 之後自動到達）
eventSource.addEventListener('suggestions', (event) => {
  const suggestions: string[] = JSON.parse(event.data);
  useChatStore.getState().setSuggestions(suggestions);
  // EventSource 在收到 suggestions 後即可關閉
  eventSource.close();
});

// 確保在 [DONE] 後仍保持連線等待 suggestions
// 注意：不要在 data: [DONE] 時立即 close()
eventSource.addEventListener('message', (event) => {
  if (event.data === '[DONE]') {
    // 設定一個 5 秒的保底計時器，如果 suggestions 沒來就關閉
    setTimeout(() => eventSource.close(), 5000);
    return; // 不立即 close，繼續等待 suggestions
  }
  // ... 原有串流解析邏輯
});
```

## 六、進階優化：Dynamic Few-Shot 自動選取

上述實作使用靜態的 Few-Shot 示例，已足夠應付大部分情況。若要達到論文中最高水準的表現，可進一步實作**動態 Few-Shot 選取**：

```python
# suggestion_service.py — 進階版（動態 Few-Shot 選取）
# 利用現有的 Qwen3-Embedding-0.6B，計算 user_query 與種子庫中
# 各示例問題的 cosine similarity，取最相近的 3 組注入 Prompt

from sentence_transformers import util
import numpy as np

# 預先嵌入種子庫（啟動時執行一次即可）
SEED_QAS = [
    {"q": "賈寶玉為什麼不喜歡讀四書五經？", "a_summary": "...", "suggestions": [...]},
    {"q": "林黛玉和薛寶釵的性格有什麼不同？", "a_summary": "...", "suggestions": [...]},
    # ... 10~15 組
]

async def select_dynamic_few_shots(user_query: str, top_k: int = 3) -> str:
    """
    根據 user_query 動態選取最相似的 Few-Shot 示例，
    對應論文 Section 4 的 'Dynamic Few-Shot Examples' 機制。
    """
    query_embedding = embedding_model.encode(user_query)
    seed_embeddings = embedding_model.encode([s["q"] for s in SEED_QAS])
    
    similarities = util.cos_sim(query_embedding, seed_embeddings)
    top_indices = np.argsort(similarities.numpy())[-top_k:][::-1]
    
    few_shot_text = ""
    for idx in top_indices:
        seed = SEED_QAS[idx]
        few_shot_text += f"用戶問題：{seed['q']}\n"
        few_shot_text += f"建議問題：{json.dumps(seed['suggestions'], ensure_ascii=False)}\n\n"
    
    return few_shot_text
```

此進階版本複用現有的 `Qwen3-Embedding-0.6B`（系統中已有），不需引入任何新模型。[^1]

## 八、已知限制與注意事項

1. **前端 EventSource 關閉時機**：必須在收到 `event: suggestions` **後**再關閉連線，而非在 `data: [DONE]` 時立即關閉。需修改現有的串流解析邏輯，加入 5 秒保底計時器。

2. **靜默失敗設計**：延伸問題生成失敗（如 API 逾時）時，後端不傳送 `event: suggestions`，前端保持靜默即可，不應影響主問答體驗。

3. **Few-Shot 種子庫的冷啟動**：需要人工標注 10~15 組高品質的（問題、回答、延伸問題）三元組。建議涵蓋人物、情節、詩詞、主題、背景等不同面向，確保多樣性覆蓋。

4. **延伸問題的可回答性**：論文強調，延伸問題必須限制在「系統有能力回答的範疇」內。透過將 `reranked_results` 注入 Prompt，可天然地確保這個約束——生成的問題必然與現有古籍片段相關。[^1]
