# 20260629 AREQA 系統架構升級計畫：引入 PELICAN 鷹架與雙系統機制

> PELICAN  的機制還沒有引入到該計畫案當中，與EDF配合一起，我覺得 PELICAN 的系統機制不錯。這嵌入至計劃之後，就更新新的系統架構圖，至計劃案中，並繼續後續的細節開發安排。

### 真實用戶驗證 (Usability Testing Insights)

解決 AI 帶來的『假性學習』: 通用ai只能單向輸出資訊，但是不能感知與了解學生的認知狀態和知識儲備，且過於被動，導致看似獲得解答，卻發生學習無效化。

### 1. 認知超載與「假性學習」 (Cognitive Overload & Illusion of Learning)
  
為了讓我們的開發焦點極度集中，並能用最簡單的話向任何人（包括 Yijia 或投資人）說明 AREQA 的價值，我們將這個系統要解決的痛點，精煉成以下三大核心問題：

- 痛點：目前的 AI (如 Gemini/ChatGPT) 習慣「一次塞給用戶整篇詳解或翻譯」。用戶以為自己看懂了，但大腦根本沒有處理與內化，一考就倒（就像你妹妹答不出來一樣）。

- AREQA 實作解決方案 : 
  - **EDF (鷹架提問系統)**：作為系統的「大腦與嘴巴 (教學策略)」。當學生發問時，EDF 負責把關**「要怎麼回答」**。它會封印通用 AI 喜歡「長篇大論給詳解」的壞習慣，強制執行資訊切塊 (Chunking)，用引導式提問確認學生內化後，才給予下一步資訊。

### 2. 系統過於被動且缺乏「同理心」 (Passive & Lacking Empathy)
  
- 痛點：學生在面對困難文本時，常常會陷入焦慮、反覆滾動螢幕，甚至不知道該怎麼發問。但現有 AI 就像冷冰冰的販賣機，你不投幣（不打字），它就不會理你；所謂的「學習模式」也只是生硬地加個問號，令人反感。

- AREQA 實作解決方案 :
  - **ComPeer (主動關懷引擎)**：作為系統的「眼睛與心臟 (同理與觀察)」。它在背景默默觀察學生的行為（滑鼠停留 Dwell、捲動、對話輪數）。它負責判斷**「何時該主動介入」**，打破 AI 的被動性，適時彈出小燈泡：「資訊量有點大，需要幫你畫圖譜嗎？」

### 3. 缺乏「先備知識」的精準診斷與長期脈絡 (Lack of Prerequisite Context)
  
- 痛點：文言文或艱澀文本的痛點往往不在「字面翻譯」，而在「缺乏歷史背景與先備知識」。通用 AI 無法精準診斷學生到底是卡在哪一層，且每一次對話都是失憶的重新開始。

- AREQA 實作解決方案 (待實作 - 結合 PELICAN 知識樹) :
  - **RAG (動態知識庫 / Space) (待實作 - PELICAN 知識樹)**：作為系統的「教科書與診斷書 (教材儲備)」。有別於一般的 RAG 只做文字比對，AREQA 的 RAG (結合 PELICAN 概念) 在處理文言文時，會預先建構出這篇文章的**「知識依賴樹」**。它讓系統知道：「要看懂這句，必須先懂這個背景」。有了這個，EDF 才知道要往哪裡搭鷹架。
  - **記憶 (GUM 動態記憶圖譜與 STITCH 記憶機制)**：作為系統的「學生輔導紀錄表 (長期追蹤)」。它負責記下學生昨天的掙扎與今天的進步。它讓 AI 擺脫「金魚腦」，知道這個學生對「貶謫文學」特別不熟，從而讓 ComPeer 在未來的日子裡，能進行真正個人化、有脈絡的長期伴讀。

## 一、 核心設計變更概覽

在確立了「不追求廣度，先將文言文領域做到極致」的策略後，現有的 EDF (鷹架) 與 ComPeer (主動關懷) 系統將進行以下升級：
1.  **放棄通用的生硬解釋**，導入 PELICAN 的「知識依賴樹 (Prerequisite Tree)」，針對文言文特性將背景知識、字義、情感分層。

## 二、 借鑑 PELICAN 升級 EDF 鷹架生成機制 (待實作)

PELICAN 論文證實，透過樹狀結構進行診斷並切換「快/慢思考」，能大幅提升學生的任務完成率與批判性思考。

### 1. 實作：文言文專屬知識依賴樹 (Knowledge State Tree) (待實作)
*   **對應痛點**：痛點 3 (前半) —— 解決「缺乏先備知識的診斷」。
*   **現況**：RAG 建庫 (Space) 僅做文本 Chunking 與 Embedding。
*   **升級作法**：當系統匯入一篇文言文（如《赤壁賦》）時，在背景處理階段，額外觸發一次 LLM Pipeline，要求模型產出該文的「知識依賴樹 JSON」。
*   **樹狀結構定義 (針對文言文)**：
    *   `Level 1 (根基)`：歷史背景與作者生平 (如：烏台詩案貶謫)。
    *   `Level 2 (表層)`：核心字詞與典故釋義 (如：羽化而登仙)。
    *   `Level 3 (深層)`：情感意涵與文學賞析 (如：豁達的人生觀)。
*   **應用**：當用戶發問或卡關時，系統能定位用戶是卡在樹狀圖的哪一個節點。

### 2. 實作：引入雙系統理論 (Dual-System Theory) 的教學策略 (待實作)
*   **對應痛點**：痛點 1 —— 解決「認知超載與假性學習」。
*   **快思考 (Fast Thinking)**：當用戶初步提問時，系統採用常規的直接解釋 (Explanation)。
*   **慢思考 (Slow Thinking)**：當前端 `log_action` 偵測到用戶在某一段落「反覆停留 (Dwell) 超過閾值」，或連續答錯時。
    *   **觸發機制**：EDF 停止給予解釋，啟動慢思考。
    *   **策略切換**：改為採用「拆解 (Decomposition)」(例如：將長句拆短) 或「類比 (Analogy)」(例如：將古代貶謫類比為現代職場被邊緣化)。
