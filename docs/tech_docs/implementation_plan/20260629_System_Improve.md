# 20260629 AREQA 系統架構升級計畫：融合 PELICAN 與 LOOM 機制

**建立日期：** 2026-06-29
**目標領域：** 灘頭堡市場 (Beachhead Market) —— 國文科文言文解析與作文批改專屬 AI 伴讀。
**核心理念：** 將最新教育學 AI 論文 (PELICAN 的知識樹與快慢思考、LOOM 的動態記憶圖譜) 轉化為 AREQA 具體的工程實作，打造具備高度同理心與深層引導能力的學習引擎。

---

## 一、 核心設計變更概覽

在確立了「不追求廣度，先將文言文領域做到極致」的策略後，現有的 EDF (鷹架) 與 ComPeer (主動關懷) 系統將進行以下升級：
1.  **放棄通用的生硬解釋**，導入 PELICAN 的「知識依賴樹 (Prerequisite Tree)」，針對文言文特性將背景知識、字義、情感分層。
2.  **優化 GUM (Global User Memory)**，借鑑 LOOM 概念，將純文字的對話紀錄轉型為「動態學習者記憶圖譜 (Learner Memory Graph)」，捕捉「未知的未知」。

---

## 二、 借鑑 PELICAN 升級 EDF 鷹架生成機制

PELICAN 論文證實，透過樹狀結構進行診斷並切換「快/慢思考」，能大幅提升學生的任務完成率與批判性思考。

### 1. 實作：文言文專屬知識依賴樹 (Knowledge State Tree)
*   **現況**：RAG 建庫 (Space) 僅做文本 Chunking 與 Embedding。
*   **升級作法**：當系統匯入一篇文言文（如《赤壁賦》）時，在背景處理階段，額外觸發一次 LLM Pipeline，要求模型產出該文的「知識依賴樹 JSON」。
*   **樹狀結構定義 (針對文言文)**：
    *   `Level 1 (根基)`：歷史背景與作者生平 (如：烏台詩案貶謫)。
    *   `Level 2 (表層)`：核心字詞與典故釋義 (如：羽化而登仙)。
    *   `Level 3 (深層)`：情感意涵與文學賞析 (如：豁達的人生觀)。
*   **應用**：當用戶發問或卡關時，系統能定位用戶是卡在樹狀圖的哪一個節點。

### 2. 實作：引入雙系統理論 (Dual-System Theory) 的教學策略
*   **快思考 (Fast Thinking)**：當用戶初步提問時，系統採用常規的直接解釋 (Explanation)。
*   **慢思考 (Slow Thinking)**：當前端 `log_action` 偵測到用戶在某一段落「反覆停留 (Dwell) 超過閾值」，或連續答錯時。
    *   **觸發機制**：EDF 停止給予解釋，啟動慢思考。
    *   **策略切換**：改為採用「拆解 (Decomposition)」(例如：將長句拆短) 或「類比 (Analogy)」(例如：將古代貶謫類比為現代職場被邊緣化)。

## 三、 借鑑 LOOM 升級 ComPeer 與 GUM 記憶機制

LOOM 論文展示了如何將零散的日常對話，無縫轉化為有延續性的個人化學習軌跡。為了維持輕量化，我們不生成完整的微型課程，而是利用圖譜來精準發動「主動關懷」。

### 1. 實作：動態標籤圖譜 (Learner Memory Graph)
*   **現況**：`compeer_scheduler.py` 中的 `run_reflection_and_initialization` 是將每日 Log 做摘要。
*   **升級作法**：修改 Reflection Prompt，要求 LLM 在每日結算時，從對話歷史中萃取「知識標籤 (Concepts)」與「精熟度 (Mastery Level)」。
*   **圖譜資料結構範例**：
    ```json
    {
      "user_id": "default_user",
      "concepts": {
        "貶謫文學": {"status": "struggling", "interactions": 3},
        "唐宋八大家": {"status": "exploring", "interactions": 1},
        "借景抒情": {"status": "mastered", "interactions": 5}
      }
    }
    ```

### 2. 實作：ComPeer 的「強化」與「探索」雙模式排程
在 `initialize_daily_schedule` 生成隔日的關懷排程時，賦予 ComPeer 兩種行為模式：
*   **強化模式 (Strengthen Mode)**：針對圖譜中狀態為 `struggling` 的標籤。
    *   *主動提示範例*：「昨天我們在貶謫文學的段落卡了比較久，今天想試著看看另一篇同樣背景的文章，確認自己是不是掌握訣竅了嗎？」
*   **探索模式 (Explore Mode)**：針對圖譜尋找「相鄰概念 (未知的未知)」。
    *   *主動提示範例*：「你已經很熟悉蘇軾的豁達了，要不要花一分鐘，對比看看同樣被貶謫的柳宗元，他的心境有什麼不同？」

## 四、 具體工程 Action Items (下一步行動)

為了將上述架構落地，優先執行以下工序：

### 1. 前端實作 (最優先)
*   **精準行為捕捉**：實作 `log_action` API 的前端呼叫，除了紀錄 Scroll 和 Dwell，需盡量**標記用戶停留的 DOM 區塊 (對應到文言文的哪一個段落)**，以利後端對齊知識樹節點。
*   **Proactive Hint UI**：實作輪詢機制，當接收到 ComPeer 排程的「強化/探索」提示時，以小燈泡或非侵入式 Toast 顯示。

### 2. 後端與 Prompt 工程
*   **更新 Space 匯入邏輯**：在建立 RAG 索引時，增加生成「知識依賴樹 (Prerequisite Tree)」的 Prompt。
*   **重構 Reflection Prompt**：修改 `compeer_scheduler.py` 中的回顧邏輯，將純文本摘要升級為 `Learner Memory Graph` 的 JSON 更新操作。
*   **升級 EDF 決策樹**：在生成回答前，加入一段判斷邏輯：「用戶是否處於 Dwell 狀態？」若是，則強制模型使用 `Decomposition` 或 `Analogy` 進行慢思考引導。

## 五、 真實用戶驗證 (Usability Testing Insights)

根據 2026-06-29 的高中生實機測試回饋（使用通用 AI 模型）:

今天看到我妹妹在利用gemini，詢問高中歷史科目的考點，而我看到gemini吐了一大堆東西給用戶(我妹妹)，但是當我詢問妹妹其中ai的知識點時，妹妹卻答不出來。可見，吐了這麼多東西給妹妹，妹妹也沒有消化進去，並且切換到學習模式也一樣，只是內容比較少，最後加一個問句，甚至用久了還會覺得煩 (就是它問的問題或回答得不在點上，還不如切換回一般問答模式。) 並且我和妹妹試了gemini的拍照問答功能。我們整理了以下三點，我這系統可以切入改善之處 :

- 主動性很重要（主動詢問有沒問題 (compeer 機制) 例如學生問到現在已經累積了一定的問題了，就跳出一個視窗，問問用戶需要幫你整理成一個知識圖譜方便理解嗎？我妹妹說這點很加分。）
- 而拍照語音說明不要太快太多，講到一個段落就問問看有沒有問題再繼續。
- 現在AI最大的問題就是一次賽給你東西，不管用戶理解還是有沒有消化，導致用戶覺得看了很多東西，但是沒有在腦袋裡思考內化了解。以及ai主動性不足，就像一個被動的人，而不是體貼人心、主動、會因學生狀況而調整說明的老師。

我們確認了當前通用 AI 的三大致命傷，並將其轉化為 AREQA 的實作優勢：

1. **主動性 (Proactivity) 是核心加分項**：
   * *痛點*：學生累積大量問題後會陷入認知超載。
   * *AREQA 解法*：除了偵測 Dwell (停留)，前端亦須加入「對話輪數計數器」。當對話累積一定數量，結合 LOOM 的概念，ComPeer 主動彈出提示：「需要幫你整理成一張知識圖譜方便理解嗎？」
2. **資訊切塊與理解確認 (Chunking & Confirmation)**：
   * *痛點*：AI 一次塞給用戶太多資訊，導致用戶只是看過而沒有內化思考。
   * *AREQA 解法*：將 PELICAN 的快慢思考落實到輸出策略中。強制模型在 Prompt 階段遵守「講到一個段落就停下來，確認學生理解後再繼續」。
3. **拒絕被動與生硬的問句**：
   * *痛點*：現有「學習模式」只是生硬地在結尾加問號，未根據學生實際盲點提問，久了令人反感。
   * *AREQA 解法*：基於 PELICAN 的知識樹，精準定位學生卡關的節點。只問與當前卡關節點相關的問題，展現如真人老師般「體貼人心且因材施教」的特質。
