這篇名為 《Grounding Agent Memory in Contextual Intent》 (簡稱 STITCH) 的最新論文（預印本，2026 年）。

  這篇論文與前兩篇最大的不同在於，它不只探討「怎麼存記憶」，更深入解決了**「在超長對話中，如何精準撈出對的記憶（意圖感知檢索）」**的問題。以下為您整理其核心內容：

  ### 1. 研究動機 (Research Motivation)
  • 現存痛點（上下文干擾）： 在長期的目標導向對話中（例如：規劃多日旅遊、長時間的辯論），Agent 常常會遇到「語意相似，但情境不同」的問題。例如，使用者可能在第一天問了 A 飯店的價格，第二天又問了 B
  飯店的價格。傳統的 RAG（僅靠語義相似度檢索）很容易因為都帶有「飯店、價格」等字眼而撈錯天的記憶。
  • 長文本模型的崩壞： 雖然現在有支援超長 Context 的 LLM（如 GPT-4o），但當對話真的太長時，它們依然會發生「迷失在中間 (Lost-in-the-middle)」的現象。
  • 缺乏適合的 Benchmark： 過去的評估資料集都太簡單了（一問一答），無法測出 Agent 在多目標穿插（例如先規劃第一天，跳去討論第三天，再回頭修改第一天）時的記憶提取能力。

  ### 2. 研究方法 (Methodology)

  作者基於認知科學的「事件結構理論」，提出了一個名為 STITCH 的記憶系統。它的核心概念是：每當 Agent 經歷一個對話步驟，不只要存下內容，還要即時為它貼上**「情境意圖 (Contextual
  Intent)」**的結構化標籤。這個標籤包含三個維度：

  1. 主題範圍 (Thematic Scope)： 紀錄目前的「宏觀目標」是什麼（例如：「第二天行程規劃」）。就算對話中途被打斷，只要目標沒變，這個標籤就會一直跟著。
  2. 事件類型 (Event Type)： 紀錄當下正在做什麼「微觀操作」（例如：「詢問價格」、「比較選項」）。
  3. 關鍵實體類型 (Key Entity Type)： 紀錄這句話討論的重點物件分類（例如：「評分」、「預算」）。
  4. 代名詞解析 (Coreference Resolution)： 存入記憶前，系統會自動把對話裡的「那個」、「他」還原成真正的專有名詞（例如把「那就訂那間吧」改成「訂 Apollo 飯店」），避免未來搜尋時找不到。

  💡 檢索方式 (Intent-Aware Retrieval)：
  當使用者發問時，系統會先預測這個問題屬於什麼「主題、事件、實體」，然後去記憶庫裡優先比對這三個標籤（Label Density
  Ranking），完全符合的才拿出來算語義相似度。這能有效過濾掉「字面很像但情境完全無關」的垃圾記憶。

  ### 3. 實驗設計 (Experiments)

  • 全新資料集 (CAME-Bench)： 作者自己做了一個非常刁鑽的測試集，專門模擬「旅遊規劃」與「政策辯論」。這個資料集充滿了各種代名詞省略、來回修改設定的長對話。分為 Small、Medium、Large（高達 40 萬
  Token）三種長度。
  • 對比 Baseline： 包含超長文本 LLM (GPT-4o、DeepSeek V3)、標準 RAG，以及最新的結構化記憶系統 (RAPTOR、GraphRAG、包含我們剛才讀的 A-MEM)。

  ### 4. 研究結果 (Results)

  • 抗干擾能力極強 (SOTA)： STITCH 在 CAME-Bench 與 LongMemEval 等資料集上取得了絕對領先的成績。在最長 (Large) 的對話測試中，表現更是遠超最強 Baseline 達 35.6%（相對提升 100%）。
  • 無懼長度增長： 其他方法（包含超長文本 LLM）在遇到 Medium 和 Large 級別的對話時，準確率都呈現斷崖式下跌。而 STITCH 因為有「主題範圍」標籤的保護，依然能保持高度穩定。
  • 消融實驗發現： 作者發現 「主題範圍 (Thematic Scope)」 是最重要的護城河；而「代名詞解析」則是實現跨對話推論 (Multi-Hop) 不可或缺的基石。
