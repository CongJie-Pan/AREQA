## 第一幕：初次對話只建立候選，不直接永久記憶

操作

建立「對話 A」，輸入 Demo 原文：

我下週要考高一物理了，但我之前連國中理化都一直不及格，現在好焦慮，你可以教我什麼是『牛頓第一運動定律』嗎？

聊天畫面驗收

- 出現「正在回顧你過去的學習紀錄」。
- 出現「正在分析目前的學習狀態與需求」。
- 回答以基礎、生活化、安撫式教學為主。
- 不應直接斷言使用者已經理解牛頓第一定律。
- 回答完成後可以正常繼續對話，不會 Loading 卡住。

記憶頁驗收

等待背景處理後，重新整理並開啟 GumPanel。

預期可看到與下列語意相符的「待確認」候選，而文字不必完全一致：

使用者目前為高一階段學生
使用者正在準備物理考試
使用者目前需要較基礎、循序的說明

這些候選必須有以下特性：

- 狀態是「待確認」，不是「已記住」。
- 不得把 AI 教學內容寫成使用者事實。
- 焦慮相關內容若被保存，必須是「待確認」。
- 不得出現「使用者已掌握牛頓第一定律」。
- 不得出現「使用者偏好星艦案例」；因為此時使用者尚未表示這是長期偏好。

此幕失敗條件

- 第一次對話就把候選直接列為「已記住」。
- AI 回答中的稱讚、教學結論被存成使用者記憶。
- 沒有任何 user evidence 卻出現候選。
- 焦慮被無確認地永久保存。

## 第二幕：Web Search 與 AI 污染隔離

操作

在對話 A 緊接著輸入 Demo 原文：

那最新的 SpaceX 星艦發射，有運用到這個定律嗎？

聊天畫面驗收

- 出現「正在查找最新資料」。
- 回答中出現 Golden Citation Chips。
- Hover citation 可顯示來源卡片。
- 回答可將牛頓第一定律與星艦情境連結。

記憶頁驗收

等待背景處理後重新整理 GumPanel。

允許出現的內容：

使用者在本次對話詢問過 SpaceX 星艦與物理定律的關係

但它應屬於「目前學習狀態」或短期脈絡，不應直接成為永久 profile。

不得出現：

使用者長期熱愛航太科技
使用者偏好以星艦理解物理
使用者已成功將牛頓第一定律應用於航太工程
使用者已掌握牛頓第一定律

除非使用者在不同對話中反覆明確表達相同偏好或事實。

此幕失敗條件

- AI 根據自己的教學結論寫入 user profile。
- 一次 SpaceX 提問就被推論為永久興趣。
- citation 或網路資料內容被誤存成使用者記憶。

## 第三幕：跨對話證據累積與自動升級

操作

建立「對話 B」，再次輸入第一幕的完整 Demo 原文：

我下週要考高一物理了，但我之前連國中理化都一直不及格，現在好焦慮，你可以教我什麼是『牛頓第一運動定律』嗎？

等待回答完成與背景處理後，重新整理 GumPanel。

記憶頁驗收

預期：

- 非敏感且在兩個獨立 conversation 都有 user evidence 的候選，可以轉成「已記住」。
- 例如「目前為高一階段學生」或「目前需要基礎說明」，是否升級由候選分類器判定，文字不要求完全一致。
- 焦慮相關內容仍應是「待確認」，不得因為重複兩次就自動升級。
- 候選 evidence 必須來自對話 A 與對話 B，不可只計算同一個對話內的重複訊息。

此幕失敗條件

- 只因同一段訊息被重送，就在單一 conversation 自動升級。
- 敏感候選自動變成「已記住」。
- profile 出現沒有對應 user evidence 的內容。

## 第四幕：使用者確認敏感候選

操作

在 GumPanel 找到與「焦慮」、「壓力」或個人狀況語意相符的「待確認」候選，點擊 Check。

重新整理 GumPanel，並建立「對話 C」，輸入：

我現在想繼續複習物理，但希望你先用不會讓我壓力太大的方式帶我開始。

驗收

- 被確認的候選從「待確認」轉為「已記住」。
- 對話 C 的回答應自然採低壓、循序、安撫的方式。
- 回答不應顯示「我根據你的記憶」等內部提示。
- 使用者 profile 與前端顯示內容一致。

此幕失敗條件

- 點擊確認後候選仍停留在待確認。
- 確認後新對話沒有使用該記憶。
- 候選確認導致其他無關候選也被升級。

## 第五幕：拒絕與抑制

操作

建立「對話 D」，輸入：

這次我只是想知道 SpaceX 星艦和牛頓第一運動定律有沒有關係，這不代表我長期對航太科技有興趣。

若 GumPanel 出現與航太興趣相關的候選，點擊 X 忽略。

接著建立「對話 E」，再次輸入完全相同的句子。

驗收

- 被忽略的候選從面板消失。
- 對話 E 不得重新建立相同語意候選。
- 被拒絕內容不得進入 profile 或主模型長期記憶注入。

此幕失敗條件

- 拒絕後同一候選立刻重現。
- 被拒絕內容仍出現在「已記住」。
- AI 在後續對話仍把航太視為使用者已確認的長期偏好。

## 第六幕：ComPeer 信箱回歸

操作

回到對話 A 或 B，閱讀回答、上下捲動，停留並等待。

驗收

- 聊天室不應被關懷訊息插話。
- 信箱紅點與信件屬非同步流程；正式環境目前延遲設定約 300 秒，請至少等待 5 至 6 分鐘。
- 若出現信件，內容可依目前學習壓力提供關懷，但不得聲稱未確認的候選是既定事實。

此幕失敗條件

- ComPeer 在聊天室中強制打斷。
- 信件引用被拒絕或未確認的長期記憶。
- 超過排程延遲後完全沒有投遞紀錄或信件。

# 最終判定

測試通過必須同時滿足：

- AI 回答絕不直接變成使用者記憶。
- 第一次 user evidence 只建立候選或短期脈絡。
- 非敏感候選在跨對話一致 evidence 後才可自動升級。
- 敏感候選必須由使用者確認。
- 候選可確認、拒絕，且拒絕能抑制重複生成。
- 新對話只使用已確認或已升級的 profile 記憶。
- Demo 的 EDF、Web Search、citation、GumPanel、ComPeer 原有功能都仍正常。
