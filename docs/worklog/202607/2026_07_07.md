繼續資料庫人工驗證工作 :

### 如何進行 Phase 1 ~ 3.5 的「人工測試確認」(Manual Verification) ?

你提到的：「我要如何確認計畫書的人工測試通過？(進行phase 1 - 3.5的人工確認?)」，你可以依照以下步驟來進行端到端的完整測試，確認你最在意的「不管在用哪個裝置登入網頁，都會同步我的資料包括對話紀錄」：

#### 步驟 1：啟動完整環境

打開終端機，執行專案的啟動指令：

npm run build
npm run start

確保 FastAPI (Backend) 與 Next.js (Frontend) 皆正常啟動。

#### 步驟 2：跨裝置同步測試 (Cross-Device Sync)

1. 開啟雙瀏覽器： 打開 Chrome (代表裝置 A) 和 Edge 或 Chrome 無痕模式 (代表裝置 B)。
2. 登入同一個帳號： 在裝置 A 與裝置 B 的網頁中，使用同一個 Supabase 帳號完成登入。
3. 裝置 A 新增資料：
    • 在裝置 A 點擊「New Chat」建立新的對話。
    • 隨意發送一則訊息。
    • 這會將資料同時存入 IndexedDB 並透過  syncService  推送到 Postgres (Cold Memory)。
4. 裝置 B 檢查同步：
    • 切換到裝置 B，此時你按下  F5  重新整理頁面。
    • 網頁應該會在初始化的  useEffect  中呼叫  syncService.pullFromCloud() 。
    • 你應該要能完整看見裝置 A 剛剛建立的對話紀錄與訊息。


#### 步驟 3：跨裝置刪除測試

1. 裝置 A 刪除資料： 在裝置 A 的側邊欄中，刪除剛剛建立的那筆對話紀錄。
2. 裝置 B 檢查刪除： 切換到裝置 B，按下  F5  重新整理頁面。該筆對話紀錄應該會自動消失。

#### 步驟 4：登出與資料安全保護測試

1. 裝置 A 執行登出： 點擊左下角的使用者選單，選擇「登出」。
2. 確認本地資料已清除： 登出後，頁面應該會重整並退回未登入狀態。你可以開啟 Chrome 開發者工具 (F12) ->  Application  標籤 -> 左側  IndexedDB  ->  PerplexityQA 。確認裡面的  conversations  與  messages 
資料表已經被清空。
3. 重新登入驗證： 再次使用該帳號登入，確認雲端資料有被正確拉回本地，並且對話紀錄全數恢復顯示。

如果你完成以上流程，並且發現行為皆如預期，代表你已經順利完成了 Phase 1 到 Phase 3.5 的所有的目標功能！
