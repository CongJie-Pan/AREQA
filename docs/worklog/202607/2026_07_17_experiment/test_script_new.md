# AREQA 人工測試劇本：記憶、回覆與 ComPeer 使用者旅程

本劇本以一般使用者實際操作為主，驗證回覆、記憶頁與信箱呈現是否符合預期；不要求測試者查詢資料庫或執行故障注入。Redis 暫時失敗後的恢復與 exactly-once 遞送屬於自動化整合測試，列於改善計畫的 Phase 5，不在本人工劇本中執行。

## 測試前置條件

- 使用新的測試帳號；記憶頁與信箱在開始時沒有本次測試留下的資料。
- 準備六個新對話，依序作為對話 A 至 F；需要不同對話時不得重複使用。
- 將 `memory_candidate_auto_promote_conversations` 設為 `2`。
- 可使用記憶頁與信箱；工程人員可在失敗時協助提供對應的安全後端事件或 HTTP 狀態。
- 每幕只需保留對話、記憶頁或信箱的截圖；第九幕另記錄停止操作時間 `T0`。

## 第一幕：敏感學習提問不形成使用者標籤

### 輸入

在「對話 A」輸入：

```text
我下週要考高一物理了，但我之前連國中理化都一直不及格，現在好焦慮。你可以教我什麼是牛頓第一運動定律嗎？
```

### 預期輸出

- 回覆以基礎、循序方式說明慣性與淨力。
- 回覆不得把使用者說成「基礎較弱／能力不足／焦慮的人」，也不得說使用者已理解或掌握定律。

### 後端查核

- 若需要釐清失敗原因，工程人員確認 ingestion 的結果為敏感內容不進入長期記憶。

### 成功標準

回覆具教學性且沒有未驗證的能力、情緒或理解程度判定；記憶頁重新整理後沒有焦慮、成績、能力或理解程度的記憶。

## 第二幕：一次性 SpaceX 問題顯示可辨識來源

### 輸入

在「對話 A」接續輸入：

```text
最新的 SpaceX 星艦發射，有運用到這個定律嗎？請提供資料來源。
```

### 預期輸出

- 若系統搜尋資料，畫面會顯示搜尋過程或完成狀態。
- 回覆能合理連結星艦與牛頓第一運動定律，並顯示可辨識的來源名稱、網域或可點擊連結。
- 回覆不得稱使用者已理解慣性或已能應用定律。

### 後端查核

- 若引用無法顯示，工程人員確認是否有對應的 `sources` 事件；不需由人工測試者分析來源資料。

### 成功標準

每個要驗證的引用都能在畫面上找到來源名稱、網域或連結；記憶頁沒有因這次單一查詢出現航太興趣、學習偏好或能力記憶。

## 第三幕：偏好問句不會被當成偏好記憶

### 輸入

建立「對話 B」，輸入：

```text
我偏好什麼學習方法？
```

### 預期輸出

- 助理可回答尚無足夠資訊，或依已存在的記憶回答。
- 不會把這個問句本身當成新的偏好內容。

### 後端查核

- 若記憶頁出現新項目，保留畫面與對應後端事件供工程人員檢查。

### 成功標準

重新整理記憶頁後，沒有因這一句問話新增偏好記憶。

## 第四幕：第一次明確偏好不會立即成為已記住的偏好

### 輸入

建立「對話 C」，輸入：

```text
我偏好用具體例子理解抽象概念。
```

### 預期輸出

- 助理可用具體例子回覆，但不應宣稱已永久記住。

### 後端查核

- 不要求人工測試者查候選資料；若記憶頁過早出現已記住的偏好，保留截圖與相關時間。

### 成功標準

在晉升門檻為 2 時，記憶頁不顯示這一筆為已記住的長期偏好。

## 第五幕：不同對話的重複偏好只顯示一筆記憶

### 輸入

建立「對話 D」，依序輸入：

```text
學抽象概念時，我希望先看具體案例或實際情境，再理解原理。
```

再於同一對話輸入：

```text
我真的比較喜歡用實際例子來學抽象概念。
```

### 預期輸出

- 第一則訊息可使偏好在兩個不同對話的條件下被記住。
- 第二則同對話重複不應再新增相同記憶。

### 後端查核

- 若出現重複記憶，工程人員可用對應的 conversation ID 與後端事件追查；人工測試只需保留畫面。

### 成功標準

重新整理記憶頁後，顯示至多一筆語意等同於「偏好用具體例子理解抽象概念」的記憶。

## 第六幕：完成暫時目標後停止提醒

### 輸入

建立「對話 E」，輸入：

```text
這個月我想完成牛頓運動定律的複習，請在這段期間協助我安排練習。
```

待回覆完成後，再輸入：

```text
我已經完成這個月的牛頓運動定律複習目標，請不要再提醒我。
```

### 預期輸出

- 第一次回覆可協助安排當月練習。
- 第二次回覆確認停止相關提醒，不把目標說成永久個人特質。

### 後端查核

- 若後續仍出現相關主動提醒，保留信箱或對話畫面與時間供工程人員檢查。

### 成功標準

助理確認停止提醒，記憶頁不把這個月的複習目標顯示為長期偏好或人物特質。

## 第七幕：明確「請記住」只記錄指定偏好

### 輸入

建立「對話 F」，輸入：

```text
請記住：我偏好你先給我一個具體例子，再解釋抽象概念。
```

### 預期輸出

- 助理可確認已處理該偏好。

### 後端查核

- 若記憶頁內容與輸入不符，保留畫面與對話給工程人員查驗來源。

### 成功標準

重新整理記憶頁後可看到該偏好；內容不額外推論能力、人格或未明說的特徵。

## 第八幕 A：編輯記憶後重新整理仍一致

### 輸入

在記憶頁選擇第五或第七幕產生的一筆記憶，將文字改為：

```text
我偏好先看生活化案例，再理解抽象概念。
```

儲存後重新整理頁面。

### 預期輸出

- 編輯後，重新整理仍顯示更新文字。

### 後端查核

- 編輯失敗時，保留 HTTP 狀態或後端錯誤訊息；不需要手動檢查儲存資料。

### 成功標準

編輯成功且重新整理後不復活舊值；任何 4xx 或 5xx 都判定本幕失敗。

## 第八幕 B：刪除已確認編輯的記憶

### 輸入

僅在第八幕 A 通過後，刪除同一筆已編輯的記憶，然後重新整理記憶頁。

### 預期輸出

- 刪除後，重新整理不再顯示該筆記憶。

### 後端查核

- 刪除失敗時，保留 HTTP 狀態或後端錯誤訊息；不需要手動檢查儲存資料。

### 成功標準

刪除成功且重新整理後舊值不會復活；若第八幕 A 未通過，本幕不執行。

## 第九幕：正常使用後 ComPeer 以信箱送達

### 輸入

在任一測試對話正常閱讀回覆並上下捲動，之後停止操作。記錄停止操作時間 `T0`，並在 `T0 + 120` 秒與 `T0 + 150` 秒檢查信箱與未讀提示。

### 預期輸出

- ComPeer 不直接插入聊天室，也不強制開啟角色扮演視窗。
- 若符合主動訊息條件，約在 `T0 + 120` 秒信箱出現一封新信，未讀數與紅點同步更新。
- 信件不把焦慮、能力推論、單次 SpaceX 問題或候選記憶說成已確認的使用者事實。

### 後端查核

- 僅在未送達或重複送達時，請工程人員依 `T0` 與帳號查詢相關 task 或安全事件。

### 成功標準

在 `T0 + 150` 秒前恰好出現一封符合內容限制的新信；若沒有新信、出現重複信或直接插入聊天室，保留 `T0`、信箱截圖與對話截圖並判定失敗。

## 最終判定

第一至第九幕皆通過，才可判定使用者旅程人工驗證通過。任一幕失敗時，記錄幕次、測試帳號、完整輸入或操作、時間、可見結果與截圖；若需工程協助，再補上對應 HTTP 狀態或安全後端事件。

Redis timeout、reconciliation 與 exactly-once delivery 不屬於人工使用者旅程，應由改善計畫 Phase 5 的單元／整合測試驗證。
