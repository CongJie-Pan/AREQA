⚠️ 現實中的落差與翻車體驗（The Pitfalls）
1. 傳說中的「自動壓縮/整理」往往失效
這點被多位開發者（如 @KSimback）在社群上吐槽。

問題： 官方宣稱「當 Context 達到 80% 時會自動進行整理壓縮」，但這其實只是寫在 System Prompt 裡的一句話。很多時候 LLM 根本沒有主動執行這件事，導致一個乾淨的 Session 聊沒多久，Context 就爆了，然後變成一個忘光光的新對話。

對 AREQA 的啟發： 千萬不要把「記憶壓縮」的決定權完全交給 LLM 自己！ 你必須在程式碼層級（Python）寫死條件，例如「只要 Tokens 達到 8000，就在背景強制啟動摘要腳本」，不能期待 LLM 會自己乖乖聽 Prompt 去整理。
