# 2026-07-21 工作紀錄

## Semantic Intake Classifier 測試觀察

- Semantic Intake Classifier 已經啟用，terminal log 也能看到分類結果。這次測試中，像是從 `明朝歷史` 改成 `春秋歷史` 這種明確更正主題的輸入，已被判定為 `topic_revision`，engine 也有正確更新 onboarding topic，而不是繼續沿用舊主題。

- 目前主要的使用體驗問題是 classifier 太積極。它會把「縮小範圍」或「補充主題方向」也當成完整的 `topic_revision`。例如測試流程中的 `春秋歷史的思想史`、`諸子百家的起源吧，我是從勞思光那本書先接觸的`，其實更適合解讀為範圍細化或背景補充，而不是要求系統重新開始 onboarding。

- 因為目前每次 `topic_revision` 都會把 onboarding 重置回 goal question，所以對話會讓人感覺在繞圈。系統會反覆更新 topic、重新詢問學習目標、再重新詢問程度背景，導致使用者感覺系統沒有吸收上下文，只是不斷重開流程。

- Classifier 需要加入中間意圖，例如 `topic_refinement` 或 `scope_refinement`。真正的 `topic_revision` 應該只在學習者明確表示「前一個主題說錯了」時才重置 onboarding。若只是 refinement，系統應更新 topic 或 goal summary，同時保留已收集的 intake slots，並前進到下一個缺少的 slot。

- 系統也需要獨立的 `background_answer` 或類似語意訊號。像 `我是從勞思光那本書先接觸的` 這類回答，應被視為背景或程度證據，而不是新主題。這能避免 engine 錯誤重啟 topic selection。

- Domain routing 對中國思想史相關主題仍不完整。`諸子百家`、`思想史`、`春秋`、`戰國`、`儒家`、`道家`、`法家`、`墨家` 等詞應該解析到 humanities route。這次匯出中，`諸子百家的起源` 被解析成 `unknown`，導致 planner 掉回 generic two-node fallback，而不是進入 humanities skill-generation path。

- 建議下一步：擴充 semantic classifier contract 與 engine state transition，明確區分 `topic_revision`、`topic_refinement`、`background_answer`；接著補齊 humanities aliases，避免中國思想史或歷史思想相關主題掉入 `unknown_domain`。
